*2. SET UP ON YOUR LAPTOP (about 10 minutes)*
--------------------------------
You need: Git, Python 3.11 or newer, Node 22 or newer.

*Step 1: get the code*
```
git clone https://github.com/ketanram-am/dayflow.git
cd dayflow
```

*Step 2: start the backend (terminal 1, from the repo root)*
```
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock
.venv/bin/python -m pip install --no-deps -e './backend[dev]'
DAYFLOW_DB=/tmp/dayflow.sqlite3 .venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8000
```
Windows: use `.venv\Scripts\python` instead of `.venv/bin/python`, and set the variable first with `set DAYFLOW_DB=%TEMP%\dayflow.sqlite3`.
Check: open http://127.0.0.1:8000/api/health. You should see {"status":"ok"...}.
Tip: a new DAYFLOW_DB path = a clean fresh demo database.

*Step 3: start the web app (terminal 2)*
```
cd web
npm ci
npm run dev
```
Open the URL that Vite prints. It sends /api calls to the backend on port 8000 automatically. If your backend uses another port: `DAYFLOW_API=http://127.0.0.1:8020 npm run dev`

*4. RULES (important, please follow)*
--------------------------------
1. Name is *Dayflow*. Never WorkSync.
2. The browser NEVER calculates money, hours, overtime or location results. It only shows what the API returns. Money strings like "1824.80" are displayed as sent (use the Money component from Prompt 0). No math on them.
3. Nothing may skip approval. Our principle is: AI proposes, the pay engine verifies, a person approves. No auto-approve buttons.
4. No new libraries. No Supabase. No hard-coded demo data. No direct `fetch` calls: use api.ts / dayflow.ts.
5. Errors come as `ApiError.message`. Show them in toasts. Every page needs a loading state, an empty state and an error state.
6. Admin-only pages must show a friendly "Administrators only" message to employees.
7. Keep your look: colours and fonts from src/styles.css, components from src/components/ui. Same style as the pages you already built.
8. Accessibility: aria-labels on icon buttons, keyboard navigation, respect reduced-motion.
9. NEVER commit a .env file, passwords or API keys.

--------------------------------
*9. TROUBLESHOOTING*
--------------------------------
- "Sign in" gives an error: backend is not running or on another port. Check http://127.0.0.1:8000/api/health and the DAYFLOW_API variable.
- Pages are empty: you are not signed in, or you signed in as an employee on an admin page.
- "Origin not allowed" (403): you opened the backend from another web address. Use the URL Vite prints, not a different host.
- Cannot check in: the admin has not set the office location yet (Settings).
- Port 8000 busy: start the backend with `--port 8001` and run the web app with `DAYFLOW_API=http://127.0.0.1:8001 npm run dev`.
- `npm ci` fails: use Node 22 or newer and delete `node_modules`.
- Want a clean demo: start the backend with a NEW DAYFLOW_DB path.
- Agent "Run" says sign the ruleset: do Policy studio, "Sign and activate", first.
- The AI model is optional. Everything works with it off (the app uses the rules). Do not try to configure it unless I ask.
